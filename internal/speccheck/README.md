# speccheck

`internal/speccheck` audits this client against a pinned Elasticsearch REST
API specification. It is run in CI (`dagger call --src . spec-check`) and can
be run locally:

```sh
SPEC_DIR=/tmp/es-spec/rest-api-spec/src/main/resources/rest-api-spec/api
go run ./internal/speccheck -spec "$SPEC_DIR"             # audit (exit 0/1/2)
go run ./internal/speccheck -spec "$SPEC_DIR" -inventory  # machine-readable rows
go generate ./internal/speccheck                           # regenerate registry + resolvers
```

## Scope and guarantees

- Checked endpoints are those whose visibility is legacy-public (`""`) or
  `public`, plus three explicitly allowlisted `feature_flag` stream endpoints.
  `_common` and `_internal*` names are excluded. The feature-flag allowlist
  never overrides `private` visibility.
- Every checked endpoint is either a verified registered implementation or an
  exact, individually reviewed entry in the baseline debt map. A new missing
  endpoint **always** fails; the baseline cannot be regenerated by
  `go:generate`.
- For a registered endpoint, every endpoint-local query parameter (regardless
  of the parameter's own visibility) and every path part must be covered by a
  real carrier field, a reviewed positional query argument, or a narrowly
  controlled exception. Path parts must map to caller-settable data.
- The registry is validated with reflection and live `ToMap()` calls: a
  deleted field, an incomplete field list, an unreachable source, or a removed
  wire key fails the audit. Response-schema parity and auditing `_common`
  globally are out of scope.

Exit codes: `0` clean, `1` coverage/registry/policy drift, `2` bad arguments
or unreadable/malformed input.

## Generator

```sh
#go:generate go run generate.go -api ../../api -bindings bindings.json -out .
```

`bindings.json` is hand-reviewed. The generator scans `api/` with `go/parser`
and emits `registry_generated.go` (the `Registry` literal, with field lists
derived from AST promotion rules) and `types_generated.go` (resolver tables
for all `api.*Params` types and service interfaces). Output is deterministic
and is compared byte-for-byte in tests. Generation never reads specs and can
never add baseline exemptions.

## Controlled ignores

The only permanent exception is the exact `format` parameter on registered Cat
JSON-decoding endpoints. The client always sends `format=json` because typed
decoding requires it; the audit re-runs `ToMap()` and asserts the controlled
value is still emitted. It is not applied to `cat.help`. Every other
exception would require an equally concrete client-controlled behavior.

## Conditional bindings

A registered endpoint that is absent from (or excluded by) the pinned catalog
must be marked `"conditional": true` with evidence explaining that it lies
outside the tag. Conditional entries do not waive parameter or path checks
when the endpoint is checked, and are not missing-endpoint baselines.

## Extension APIs

When a service method has no query carrier or no path selector, an opt-in
extension interface is added instead of changing the existing interface:

```go
ext, err := api.AsAsyncSearchServiceSpecExtensions(searchService)
if err != nil { /* custom implementation without support */ }
resp, err := ext.StatusWithParams(ctx, id, &api.AsyncSearchStatusParams{KeepAlive: "1m"})
```

The default implementation always satisfies the extension; the adapter rejects
nil, typed-nil, and custom services without support with a descriptive error.
The original method keeps delegating with nil params, so existing callers are
source-compatible.

## Stale-entry examples

The audit fails when:

- a baseline endpoint is implemented (overlap) — remove the baseline entry and register a binding;
- a baseline endpoint disappears, becomes private/excluded, or changes stability/visibility — update or remove the entry;
- a baseline entry has no reason, tracking anchor, or a status other than `not-implemented`/`experimental`;
- a registered binding is absent from the catalog without `conditional` evidence.
