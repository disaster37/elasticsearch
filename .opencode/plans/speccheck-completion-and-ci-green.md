Exact reader behavior:

- Absent/null/empty params means no endpoint-local params. Param descriptors must be objects; nonempty parameter names and valid string metadata are required. Unknown param types remain loadable but the inventory marks them for explicit typing; the generator must not silently invent a Go type.
- Preserve endpoint and parameter stability/visibility separately. `Checked`: skip `_common`, names beginning `_internal`, and endpoint visibility other than `""` or `"public"`, except an explicitly allowlisted `feature_flag` endpoint. ### 4. Implement the endpoint ratchet and narrowly justified parameter exceptions

Add `internal/speccheck/policy.go`, `policy_test.go`, and `baseline.go`.

```go
type MissingEndpoint struct {
    Status string // "not-implemented" or "experimental"
    Reason string // concrete missing service/method; never merely "skip"
    Stability string // exact pinned metadata, including empty if absent
    Visibility string // exact pinned metadata
    Tracking string // local README backlog anchor or real issue URL

    Reason string
    ControlledValue string // nonempty for client-controlled wire values

}

    Checked, Implemented, KnownMissing, Ignored int

Experimental status describes existing deferred experimental endpoints; it is not blanket immunity for new experimental APIs.

Critical audit logic, in order:

1. Validate registry and policy before endpoint comparisons; retain errors in results.
2. For each checked endpoint in sorted order: if absent from registry, count KnownMissing only if its exact valid baseline entry exists; otherwise append MissingEndpoints. If registered, count Implemented and check all local params/parts.

- Deleting a registered service/type/method, losing a query field/ToMap key, or losing a bound path source fails. Regenerating registry cannot add missing-endpoint exemptions.

If present with feature_flag/public visibility they are audited; private visibility is never overridden. No broad prefix allowance.
- Parameter exception references must target a checked registered endpoint and an existing spec param. Missing params/endpoints, redundant exposed/positional params, empty reasons/evidence, or unsupported uncontrolled exceptions fail.
